## Technical Decisions

<Card>

### Decision 1: Utilized Firebase for Backend Services

- **Why**: As a solo frontend developer aiming for rapid delivery, building a secure and real-time backend from scratch was not feasible.
- **Result**: Leveraged Firebase services to build a full-stack web application with secure user management and real-time data synchronization.

<Divider borderStyle="dashed" gap={4} />

### Decision 2: Integrated Redux for State Management

- **Why**: Managing global state with React Context API led to excessive prop drilling and redundant database reads.
- **Result**: Introduced Redux to manage global state, reducing prop drilling and cutting redundant database reads, resulting in a leaner data flow and single source of truth.

<Divider borderStyle="dashed" gap={4} />

### Decision 3: Deployed on GitHub Pages for Demo

- **Why**: Needed a quick and cost-effective way to deploy the application for global access.
- **Result**: Deployed the application on GitHub Pages, ensuring easy access for users worldwide.

</Card>

## Challenge: Product Management

<Callout>

- **Challenge**: Being too ambitious and trying to get everything perfect at once caused the schedule to be delayed again and again.
- **Solution**: Apply the **Minimum Viable Product (MVP)** principle by modularizing and prioritizing all features based on their strategic importance and business value. This allows for a swift initial launch, followed by an iterative process of rolling out the remaining functionalities as well-planned modules.

</Callout>
